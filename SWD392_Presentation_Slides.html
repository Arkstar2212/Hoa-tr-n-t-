KIẾN TRÚC & THIẾT KẾ PHẦN MỀM

Đồ án Game 2.5D Narrative Adventure: Hoa trên đất đỏ

Nền tảng: Unity 6 (URP) | C# 9+ (.NET Standard) | Cinemachine 3 & New Input System

Báo cáo viên: Nhóm Đồ Án Kỹ Thuật Phần Mềm

1. BÀI TOÁN & THÁCH THỨC THIẾT KẾ

Bối cảnh & Nghiệp vụ Game

  • Thể loại: 2.5D Historical Narrative Adventure Nam Bộ thập niên 1950.
  • Kết hợp giữa đi cảnh màn hình ngang (2.5D platforming) với các đoạn chuyển cảnh điện ảnh 3D tự do (Cinematic 3D Orbit).
  • Cốt truyện phi tuyến tính: Cây hội thoại phân nhánh & tương tác NPC (Genshin-style dialogue flow).

Thách thức Kiến trúc (SWD)

  • Tight Coupling: Các hệ thống Player, Camera, Cutscene, Audio, UI rất dễ bị phụ thuộc chéo lẫn nhau nếu không phân lớp tốt.
  • Control Handover: Cơ chế bàn giao quyền điều khiển (Gameplay ↔ Timeline Cutscene) phải mượt mà, triệt tiêu race-condition.
  • Performance: Duy trì chuẩn 60 FPS, Zero Memory Leak và Garbage Collection allocation tối thiểu.

2. YÊU CẦU PHẦN MỀM (FURPS+ MODEL)

FR Functional Requirements

  • Locomotion Subsystem: Di chuyển 2.5D, nhảy vật lý, bám dây thừng, tương tác bến thuyền.
  • Dialogue Subsystem: Cây hội thoại ScriptableObject, hỗ trợ hiển thị có dấu UTF-8, trigger quest.
  • Cinematic Director: Tự động kích hoạt Cutscenes (Sunset Boat, Village Pier), blend camera mượt.
  • Save/State System: Checkpoint lưu vị trí và cờ cốt truyện.

NFR Quality Attributes

  • Performance: Frame rate ≥ 60 FPS, Render budget < 16.6ms, GC Alloc < 1KB/frame.
  • Modularity & Extensibility: Thêm màn chơi, cutscene hay NPC mới không can thiệp code nhân vật.
  • Portability: Dùng Unity New Input System, tương thích Keyboard, Mouse, Gamepad.
  • Reliability: 0 Missing Inspector References, cơ chế Fail-Safe khi cắt ngang cutscene.

3. KIẾN TRÚC TỔNG THỂ (LAYERED + EVENT-DRIVEN)

Phân tầng 4 Lớp (Tiered Architecture)

1. Presentation Layer: UI Canvas (TextMeshPro), Cinemachine Virtual Cameras, VFX.

2. Business & Gameplay Logic: Character Locomotion, Cutscene FSM, Dialogue Controller.

3. Core Services Layer: Game Event Bus, Input Action Providers, Audio Managers.

4. Data & Asset Layer: ScriptableObjects (Quests, Dialogues), URP Shaders, Audio Assets.

┌───────────────────────────────────────────────┐ │ PRESENTATION (UI, V-CAM, VFX) │ └───────────────────────┬───────────────────────┘ ▼ ┌───────────────────────────────────────────────┐ │ GAMEPLAY LOGIC (Character, Dialogue) │ └───────────────────────┬───────────────────────┘ ▼ (C# Events / Actions) ┌───────────────────────────────────────────────┐ │ CORE SERVICES (EventBus, Input, Audio) │ └───────────────────────┬───────────────────────┘ ▼ ┌───────────────────────────────────────────────┐ │ DATA & ASSETS (ScriptableObjects, URP Data) │ └───────────────────────────────────────────────┘

4. MÔ HÌNH 4+1 VIEW MODEL

1. Logical View: Phân chia các gói domain: Scripts/Camera, Scripts/Cutscenes, Scripts/Dialogue, Scripts/Player với giao diện Interface tường minh.

2. Process View: Tách biệt luồng vật lý (FixedUpdate 50Hz) với luồng logic (Update) và luồng bất đồng bộ (Coroutines/Async cho Cutscene & Tweening).

3. Development View: Tổ chức C# Assembly Definition Files (.asmdef) riêng biệt cho Editor và Runtime, đảm bảo build không rò rỉ Editor code.

4. Physical / Deployment: Đóng gói Standalone Player (.exe x86_64) với Universal Render Pipeline 2D/3D Batching.

+1. Scenarios (Use Cases): Trục cốt lõi: Người chơi kích hoạt Trigger Bến Thuyền → Khóa Input → Timeline diễn hoạt thuyền rời bến → Camera trả lại góc chơi game.

5. CÁC DESIGN PATTERNS CHỦ CHỐT

BEHAVIORAL

Observer / Event Bus

Giao tiếp giữa Director và Character thông qua C# Action Delegate. Triệt tiêu 100% hard-references giữa Cutscene và Player.

BEHAVIORAL

State Pattern (FSM)

Quản lý trạng thái nhân vật: LocomotionState, RopeClimbState, InCutsceneLockedState. Loại bỏ chuỗi if-else cồng kềnh.

CREATIONAL

Singleton / Service

Áp dụng cho IntroAudioController, SaveSystem. Kiểm soát vòng đời tập trung với DontDestroyOnLoad an toàn.

6. CHI TIẾT THIẾT KẾ & ÁP DỤNG SOLID

Luồng Bàn Giao Cutscene (Handover)

  • Single Responsibility (SRP): BoatSunsetCutsceneDirector chỉ lo kích hoạt Timeline & Camera; không can thiệp code di chuyển vật lý của Player.
  • Open/Closed (OCP): Thêm màn cắt cảnh mới chỉ cần tạo thêm class cài đặt ICinematicDirector mà không phải sửa PlayerController.
  • Dependency Inversion (DIP): Module tầng cao không phụ thuộc module tầng thấp; cả hai phụ thuộc vào Event Interface trung gian.
[BoatSunsetCutsceneDirector] │ (Fires Event) ▼ [GameEventManager.OnCinematicTriggered(true)] ┌─────┴────────────────┐ ▼ ▼ [PlayerController] [HUDController] SetInputLocked(true) FadeOutUI() StopPhysicsVelocity()

7. DATA ARCHITECTURE & ASSET INTEGRITY

Data-Driven Architecture

  • ScriptableObject Architecture: Tách biệt triệt để Logic xử lý khỏi Dữ liệu nội dung (Content).
  • Dữ liệu lời thoại, cây nhánh và thông số nhân vật được lưu dưới dạng Asset (.asset), cho phép Narrative Designer chỉnh sửa trực tiếp không cần compile code.

Asset Integrity & Performance

  • Asset Pipeline: Bảo tồn nguyên bản tranh màu nước và quy chuẩn lịch sử Nam Bộ 1950.
  • Memory Management: Sử dụng Texture Atlasing và Sprite Mesh Caching trong URP, hạn chế tối đa Draw Calls khi hiển thị background parallax nhiều lớp.

  • Đã hiện thực hóa kiến trúc phần mềm chuẩn mực cho game narrative 2.5D, kết hợp mượt mà giữa Event-Driven và Layered Architecture.
  • Bảo đảm đầy đủ các chỉ số chất lượng: Hiệu năng cao (60 FPS), tính mở rộng cao, dễ dàng bảo trì và tích hợp nội dung mới.
